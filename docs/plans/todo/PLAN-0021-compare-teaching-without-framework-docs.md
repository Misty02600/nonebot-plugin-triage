# PLAN-0021：对照框架文档对教学生成的实际贡献

| 状态 | 最后更新 |
|---|---|
| 暂缓 | 2026-09-14 |

## 背景与边界

项目作者认可做有／无框架文档对照，但明确要求记录暂缓，当前优先修复检索和完善 RAG 评测。
v106 冷测中，关闭 JM 的 got 确认步骤、Steam 查询的执行边界引用了文档，但引用不能证明文档不可替代。
不同 revision 冷测还包含其他变更，不能作为文档作用的因果对照。

## 技术路线

后续复用 `tools/nbtriage_maintainer/teaching_eval.py` 与 `capability_teaching_evaluation.py` 的现有执行、捕获和
复评入口。选取 got、finish/CommandArg、regex 输入表示以及只重复已有证据的少量案例，固定源码、初始 Evidence、
模型、Prompt、输出合同、预算和语料。在文档可用与不可用两组间仅改变框架文档工具可用性，保留源码导航。
收尾环节及其独立预算在两组中一致；保存完整初始输入，避免无法核对预组装框架语义的混杂因素。

这是整个文档工具的增益评估，工具关闭后模型改变导航策略属于可观察结果。若只想测某篇文档的信息贡献，
应另行定义固定上下文实验，不能混用两种结论。运行前确认模型和成本边界；暂缓期间不触发付费实验。

## 完成标准与验证

- 对关键 usage、场景约束、交互步骤和行为边界逐项盲审；记录两组错误、缺失与正确情况。
- 同时记录工具次数、来源、预算阻止和模型用量；重复运行以观察波动，不以单个引用作为成功判据。
- 复用本地报告与来源摘要，明确小样本限制。开发回归集不能冒充独立冷测。
- 结论能够区分“文档提供了正确事实”“事实进入教学”“文档改善生成质量”，无充分证据时明确无法归因。
