# ADR-0005：首个群报障交互采用精确回复触发与窄回显

| 状态 | 决策日期 |
|---|---|
| 已被 [ADR-0006](0006-cross-platform-alconna-entry-and-reference-providers.md) 替代 | 2026-08-09 |

## 背景

OneBot V11 已能把结构化回复引用解析到运行证据，但还没有用户可触发的 Matcher。入口若允许自由文本、
任意历史查询或直接回显插件 / 栈信息，会把第一版重新变成静默聊天分析或日志查询器；若只允许管理员提交，
又无法验证普通群员在问题发生点保留现象的价值。

## 决策

1. 首个 OneBot 群入口要求同时满足：群消息、回复一条结构化消息、`to_me()`、纯文本精确为“报错”；
2. 任意群成员都可提交。入口不接收附加描述，不把用户文字送入模型或工具；
3. 以进程随机密钥对 Bot / 群 / 用户 scope 做 HMAC 后限流，同一 scope 默认 30 秒一次；原始身份不保存；
4. 默认运行观察与消息引用 TTL 为 900 秒；观察容量 10,000，引用容量 4,096。部署者可以通过 NoneBot
   插件配置覆盖，核心类仍无隐藏默认值；
5. 报障成功后保存不含身份与正文的进程内 `LiveIncident`，默认最多 256 条、保留 86,400 秒；重启即丢失；
6. 群内只返回不透明受理编号、是否存在明确失败观察、保留窗口和隐私说明。没有详情查询命令；
7. 引用缺失 / 过期只提示重新回复近期消息，限流只提示稍后重试，不按时间猜测关联；
8. 当前入口不调用 DeepSeek、不创建 GitHub Issue、不运行 Probe、不修改配置或重启 Bot。

## 选择理由

- 精确结构化触发避免把普通群聊或复杂插件命令误判为报障；
- 普通用户能在现象发生点提交，而窄回显阻止其借报障入口读取内部日志；
- 15 分钟窗口足以首轮 dogfood，同时限制运行元数据和消息引用的驻留；
- 先形成可审计 `LiveIncident`，后续模型诊断可以消费脱敏对象，不需要重新读取聊天记录；
- 命令文本与限流均可配置演进，但第一版没有自然语言解析和代执行行为。

## 限制

- 用户暂时不能补充现象描述；错误行为但无异常时只记录为显式疑似故障；
- 进程重启会清空报告和引用，当前不适合多 Worker 或跨重启 SLA；
- 普通群员不能查询状态，维护者查看 / 导出与 DeepSeek 诊断需要后续独立权限设计；
- 默认值是首轮 dogfood 基线，不是对所有规模 Bot 的容量建议。
