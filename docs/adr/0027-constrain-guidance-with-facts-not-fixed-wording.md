# ADR-0027：用事实输出合同约束能力帮助，不固定模型话术

| 状态 | 决策日期 |
|---|---|
| 已采纳 | 2026-08-12 |

## 当时遇到了什么

ADR-0026 已经决定在检索和模型前排除普通用户无权感知的能力，但仍以“同一通用未命中回复”和少量固定
示例描述输出。这样容易把安全边界、事实完整度和具体措辞混成一件事：提示词为了守边界而规定机械话术，
同时又可能把公开能力真实存在的群聊 / 私聊条件、管理员要求或限流额度压缩成“可能受限”。

普通用户有理由知道一个已经公开的能力怎样才能正常使用；模型也应该能根据问题自然组织语言。需要固定的是
模型可以读取和表达的事实，而不是每次回复必须出现的句子。

## 决策

1. `ServingView` 向回答层提供“允许表达的事实”和“禁止表达的事实”。模型可以自行决定句式、详略和是否
   追问；提示词不得把某一句未命中、限流或权限文案规定为唯一合法回复。
2. 未命中仍满足 ADR-0026 的不可区分性：`review`、`restricted`、hidden、SUPERUSER-only、operator deny
   和其他 adapter 的能力在召回与模型上下文前已经被排除，回答不得根据它们暗示能力存在。用户可访问的
   证据确实没有命中时，模型可以自然表达“没有找到相关功能”；只有请求本身含糊时才按需要澄清，不强制
   要求用户换一种说法。
3. 对已经 `public` 的能力，只要有 revision 对齐且可引用的 Evidence，就尽量给出用户可观察的执行约束：
   - 必要输入或前置动作；
   - 群聊 / 私聊等使用场景；
   - 群管理员、群主、成员或其他公开角色要求；
   - 是否存在限流，以及可确认的作用对象、作用域、额度、窗口、冷却或重置方式；
   - 已确认的启用状态或需要管理员完成的非秘密部署条件。
4. “公开能力存在执行约束”和“能力本身受限”必须分开：
   - 整项能力被判定为 hidden、SUPERUSER-only、operator deny 或 `restricted` 时，普通用户路径不读取其
     代码、Claim 或约束，也不说明它只限管理员；
   - 能力本身已经 `public` 时，可以说明群管理员、场景、限流等正常使用条件；若只有某个子操作受限，
     不得借说明公开部分暴露受限子操作。
5. 普通回答只表达用户可观察的含义，不展示 Permission / Rule 类名、限流库或 API、配置字段、源码位置、
   内部后端及证据状态术语。adapter 仍是披露域硬边界，不主动告诉用户另一个平台是否存在对应能力。
6. 约束证据不足时可以省略或明确不确定，不能猜测具体额度、身份条件或当前剩余额度。只有安全的运行回执
   或专用无副作用 evaluator 才能把静态规则说明提升为“你这次已经通过 / 被拒绝”的当前判断。
7. 第一版事实合同可以先用可扩展 payload 表达约束类型、主体、作用域、额度 / 时间窗口、场景、角色、
   Evidence 与 revision，不在本 ADR 固定数据库列或通用权限 DSL。

## 为什么这样选

- 安全由模型前的数据域和输出事实校验保证，不依赖模型背诵一句拒答模板；
- 模型可以根据用户问题自然回答，避免为了安全产生机械、误导或重复追问；
- 公开能力的真实限制是用法的一部分，隐藏这些事实会让教学本身失去价值；
- restricted 能力与 public 能力的执行约束分开后，既不泄露内部入口，也不会把正常权限和限流说得含糊。

## 没有采用的方案

- **为每种未命中、限流和权限情况固定一句回复**：文案难以覆盖上下文，也把风格测试误当安全测试。
- **只说“可能受限”**：已经确认的群聊条件、管理员要求或限流额度没有被利用，用户无法据此行动。
- **只要发现管理员条件就隐藏整项能力**：会错误隐藏面向普通用户公开、但某些场景要求群管理员的功能。
- **先把所有约束交给模型再要求它保密**：内部类型、字段和受限能力已经进入上下文，违反 ADR-0026。

## 带来的影响

- 模型回复评测应检查事实支持率、约束遗漏、越权披露和误导性绝对结论，不以逐字匹配固定话术为目标；
- 确定性降级路径仍可使用稳定文案，但它只是当前实现，不是未来模型回答的产品合同；
- 能力知识需要逐步从布尔可见性扩展到披露判定与执行约束分离；
- 常见 NoneBot 权限和限流工具可以按版本复用解释知识，但回答不暴露底层实现名。

## 落实与确认

- **当前已有**：普通用户优先读取显式公开 Provider，并可读取当前 adapter 自动确定 public 的影子命令；
  `review / restricted` 仍在模型外隔离。能力分析客户端只有库级假模型测试，未接产品 handler。
- **本次最小落实**：确定性无命中回复改为中性表述，不再暗示存在被过滤能力或强制用户换一种说法。
- **尚未实现**：`is_visible` 目前仍同时承担披露和当前上下文可见性，`PublicCapability` 也没有结构化约束；
  除 SUPERUSER 外，大部分 Rule、Permission、限流和 handler 条件仍是 `opaque`。因此现行回复还不能声称
  已经精确说明额度、管理员要求或群私聊条件。
- 本 ADR 不授权执行第三方权限、限流或 handler，也不授权启动新的模型调用。

## 替代关系

- 细化 [ADR-0026](0026-filter-capability-knowledge-before-retrieval.md) 的回答投影：保留检索前隔离和不可区分性，
  但把“同一回复”解释为可访问事实不可区分，而不是固定字面模板；
- 延续 [ADR-0024](0024-auto-publish-deterministic-capability-fields.md) 的“确定且低风险字段自动 public，
  动态、冲突、敏感或证据不足项才 review”边界；
- 不改变 [ADR-0025](0025-explain-plugin-behavior-from-deployment-evidence.md) 的 EvidenceUnit 与开发者诊断边界。
