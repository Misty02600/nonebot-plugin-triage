# ADR-0141：Bug 调查结束后不再自动追问

| 状态 | 决策日期 |
|---|---|
| 已采纳 | 2026-09-14 |

## 问题与决定

正式服务联测中，Agent 因配置、运行记录和会话证据不足返回 unknown。证据校验因引用 partial
会话记录清空了具体缺口，后续程序又按通用证据类别要求用户补充操作，未结束调查。
缺少运行或日志证据并不等于用户能够补齐；目前没有实际案例支撑调查后的定向追问机制。

用户确认采用以下边界：

- 调查前的意图、对象和操作澄清以及公开初检，继续共用原有两次补充额度。
- 真实调查返回后不再按 missing_evidence 类别自动追问；未知结果说明限制并关闭当前 Thread。
- 对象无法定位或没有异常观察时，保留调查准入澄清、额度检查和重复问题检查。
- 引用不存在仍按无效引用处理；确定结论引用陈旧或不完整证据仍降级。
- 候选已经是 unknown 且引用存在时，陈旧或不完整证据仍触发原降级，但保留候选的具体缺口；
  不保留由此无法确认的次数、责任或引用，不生成缺陷报告。

## 取舍与范围

放弃少量调查中途才发现的用户追问机会；有真实需求时再评估，不新增模型调用、状态字段或自动恢复机制。
用户之后主动提供新信息，可以发起新的显式求助。正式 Bug 入口仍暂停，测试显式临时启用。

本决定局部替代 [ADR-0143](0143-share-two-supplements-across-support-and-bug-assessment.md)
中调查后按证据类别补充的行为；两轮上限与调查前问答保留规则不变。
当前流程见[支持入口与意图路由](../architecture/flows/support-intake-routing.md)。

## 验证

证据校验回归覆盖无效引用、陈旧/partial 引用及确定/未知候选；Handler 测试确认调查首次未知就关闭，
前序澄清仍有效。原正式服务场景在不改变 Bug Prompt 的情况下重跑通过：具体缺口保留、一次最终回复、
Thread 关闭、无活动 scope、无 Bug 记录命令或仓库写入。单次真实模型结果不代表稳定性或发布资格。
