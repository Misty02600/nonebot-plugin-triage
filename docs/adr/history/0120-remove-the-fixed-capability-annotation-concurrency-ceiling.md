# ADR-0120：取消教学注释并发的固定数值上限

| 状态 | 决策日期 |
|---|---|
| 已采纳 | 2026-08-24 |

## 当时遇到了什么

ADR-0096 将教学分析改为按 teaching unit 使用同一个全局 semaphore，同时把配置固定在 `1..32`。
真实整项目验证需要让全部待生成单元同时进入分析，以观察 Provider、连接池和单元状态在高并发下的实际
边界；固定 32 是项目自行选择的经验值，不是 Pydantic AI、Provider 或缓存发布协议要求的正确性上限。

## 最后决定

1. `NBTRIAGE_CAPABILITY_ANNOTATION_MAX_CONCURRENCY` 继续表示同时运行的教学单元数，默认值保持 `10`，并且
   必须为正整数。
2. 项目不再为该配置设置固定数值上限。部署者根据 Provider 限流、HTTP 连接容量、token 速率、费用和机器
   资源选择数值；把数值设置得不小于待生成单元数时，等价于当前刷新内不由 semaphore 额外限流。
3. 不新增 `0`、`unlimited` 或其他特殊值；配置解析与运行时始终接收明确的正整数。
4. 全局 refresh lock、teaching unit 独立 Agent、源码复核、缓存 staging 和原子发布边界保持不变。取消数值
   上限不改变单元预算、Provider 重试或全局停止语义。

## 为什么这样选

- 数值 32 不承载安全或一致性不变量，保留它只会阻止部署者按实际环境选择更高并发；
- 正整数保持配置语义简单，避免让 `0` 同时承担禁用或无限并发两种可能解释；
- semaphore 和发布串行化继续保留，高并发只扩大模型分析阶段，不改变持久化事务边界。

## 带来的影响

- 有利：整项目首次生成或代码变化后的重建可以让全部待生成单元同时开始分析；
- 代价：过高配置可能触发 Provider 限流、连接失败、token 峰值和费用峰值，项目不再替部署者设置保护上限；
- 代价：高并发下日志完成顺序更不稳定，诊断仍需依赖 `refresh_id`、插件和 teaching unit ID 关联；
- 默认部署行为不变，未配置时仍使用并发 `10`。

## 落实与确认

- 配置模型只保留 `ge=1`，服务构造器只验证正整数；
- 回归验证较大的正整数可以通过配置，`0` 仍被拒绝；
- 使用一个真实多插件下游部署验证并发高于待生成单元数时的 Provider 与发布行为：全部 pending teaching
  unit 均能同时进入分析，说明原固定上限已实际移除；高并发下也出现了部分单元达到 300 秒超时。该结果
  支持取消项目固定上限，但不支持把无限制并发作为默认部署值。

## 替代关系

- 替代 [ADR-0096](0096-bound-capability-annotation-concurrency-by-unit.md) 第 2 项中的 `1..32` 固定范围。
- ADR-0096 的 teaching unit 调度、全局 semaphore、失败停止和发布边界继续有效。
