# ADR-0001：以 QQ 群显式报障关联 NoneBot 本机运行证据

| 状态 | 决策日期 |
|---|---|
| 已采纳 | 2026-08-08 |

## 背景

当前 NoneBot Triage Agent 从公开 GitHub Issue 构造 `SupportCase`，已经验证证据隔离、补证策略、审批和
Oracle 结果关联，但真实用户入口仍然缺失。独立 Bot 部署者面对的实际问题通常发生得更早：群友只知道
“某个功能没反应”“刚才命令报错”或“Bot 发了奇怪的内容”，不知道插件名、Matcher、适配器、调用阶段
和日志位置。维护者需要再按消息时间手工翻日志、猜责任插件，GitHub Issue 往往是在上下文丢失后才建立。

竞品调研表明，“从群聊中识别 Bug”本身已经不是空白能力。AstrBot BugCatcher 已支持静默监听群聊、
批量调用 LLM 识别和去重 Bug，并在 Dashboard 中处理记录。NoneBot 官方也已经提供 Sentry 插件做错误跟踪。
NoneBot Triage Agent 若只增加聊天分类器或异常上报，会成为现有产品的弱重复。

## 决策

NoneBot Triage Agent 的首个真实用户入口采用可安装在独立部署者 Bot 中的 NoneBot 入口插件，先支持 QQ 群中的
**显式报障**，并把报障与 Bot 本机的有界运行证据关联。入口示例可以是群友回复一条异常消息后
`@Bot 报错`，或由维护者把指定消息转为报障；具体命令语法不在本 ADR 中冻结。

产品链路冻结为以下边界：

1. 本机采集器为事件分配关联标识，保留有界、可配置且经过脱敏的事件证据；候选证据包括事件时间与类型、
   实际运行过的 Matcher、插件 / 模块身份、处理阶段、平台 API 调用结果、异常摘要和版本 / 配置指纹。
2. 用户显式报障后，入口只提取被回复消息、必要的邻近上下文和关联标识，构造传输无关的
   `SupportCase` / `SupportSession` 输入。QQ、OneBot 与 NoneBot 类型不得进入领域核心。
3. Agent 先判断已有证据是否足够，再按冻结策略每轮最多补问一个高价值问题；不能把整段原始日志直接交给
   群友，也不能允许普通群员查询任意日志。
4. 原始群聊与原始日志默认不上传、不长期保存；只有最小化且脱敏后的证据可以进入模型边界。完整的保留时长、
   群内告知和管理员配置将在实施计划前单独冻结。
5. 用户报障只创建内部支持会话，不自动创建 GitHub Issue。扩大日志范围、运行 Probe、创建 Issue、评论、
   标签或代码变更仍需维护者明确审批，并保留来源、动作和结果的审计事件。
6. 第一阶段在维护者自己的 Bot 与 QQ 群中 dogfood，优先验证是否减少翻日志和反复追问，而不是先建设多租户
   SaaS、通用 Dashboard 或全平台入口。

## 选择理由

- 报障发生点仍保留消息、事件和运行时上下文，比事后 GitHub Issue 更容易形成可行动证据；
- NoneBot 官方提供的事件、Matcher 运行前后和平台 API 调用钩子，使责任链采集在技术上具备明确入口；
- 已有 B1 / B3 的证据缺口、单步补问、审批和 Oracle 资产可以复用，不需要退化成新的聊天 Demo；
- 显式触发比全群静默监听更容易建立隐私边界，也减少普通聊天被误判为 Bug 的模型费用和噪声；
- 产品差异落在 NoneBot 责任层定位与证据闭环，而不是模型摘要能力。

## 否决的替代方案

### 继续只做 GitHub Issue 分析

保留评测价值，但无法验证最终用户入口，也无法解决维护者最耗时的“把现象和本机日志对上”步骤。

### 静默监听全部群聊并让 LLM 自动发现 Bug

与 AstrBot BugCatcher 的能力高度重叠，同时扩大隐私、误报、存储和模型成本风险。后续可以把自动发现作为
可选模式研究，但不作为默认 MVP。

### 只接入 Sentry

能获得异常与 breadcrumb，但不能覆盖“没有抛异常却行为错误”、普通用户的自然语言现象、NoneBot
Matcher / 插件责任边界和逐步补证。Sentry 可以成为后续证据源，不是产品核心的替代品。

### 自动把群友反馈写成 GitHub Issue

会放大误报、隐私泄露和外部写入风险，也跳过 NoneBot Triage Agent 已建立的证据完整性与审批边界。

## 结果与约束

正向结果是项目从离线评测进入真实业务闭环，同时保留证据优先与安全审批的主线。代价是需要处理
NoneBot 钩子兼容、关联标识传播、并发事件、日志脱敏、保留策略和插件共存，工程复杂度明显高于群聊分类器。

以下事项尚未由本 ADR 决定：

- NoneBot 入口与 NoneBot Triage Agent 核心采用同仓多包还是独立插件仓库；
- 默认证据保留时长、最大容量、群内告知文本和管理员导出策略；
- 首版是否直接读取 Sentry 事件，或先使用本机结构化环形缓冲；
- QQ 官方适配器与 OneBot V11 的先后顺序和消息引用兼容范围；
- 真实 dogfood 的成功门槛与前向隐藏评测批次。

这些问题在创建实施计划前处理；在此之前不得把“已采纳方向”描述为“已经实现”。
