# ADR-0028：允许 triage 私聊并向 SUPERUSER 原会话返回行为解释

| 状态 | 决策日期 |
|---|---|
| 已采纳 | 2026-08-12 |

## 当时遇到了什么

ADR-0006 为首个群聊报障切片统一拒绝私聊，本决定形成时 `triage` Matcher 也在意图分类前执行这条限制。随着
`triage <自然语言>` 被确定为统一支持入口，以及 ADR-0025 采纳面向已鉴权开发者的插件行为探索，这个
全入口场景限制已经过宽：私聊本身并不妨碍文本守门、意图分类、公开教学或模型外 `SUPERUSER` 鉴权。

另一方面，行为探索可能返回获准披露的源码位置、配置影响和 restricted 部署事实。此前候选方案试图再校验
群聊或频道的成员构成，或者强制把完整解释转到私聊 / allowlist 房间。但会话是否适合让其他参与者看到这些
内容，本来就可以由已经通过部署级 `SUPERUSER` 鉴权的请求者选择；系统既无法可靠证明所有旁观者的身份，
也不需要代替开发者决定使用私人群聊、隔离服务器还是公开运维频道。

这里必须把两类边界分开：`SUPERUSER` 可以承担**提问会话可见范围**的选择责任，但不能取消秘密过滤、
证据新鲜度、只读采集或远端模型数据外发限制。

## 决定

1. `triage <自然语言>` 统一入口允许私聊、群聊和频道请求进入相同的本地输入守门与意图分类；不为私聊增加
   第二套命令，也不要求行为探索使用显式子模式；
2. 私聊只是一种请求会话，不改变意图。教学、用法纠错、行为探索和疑似故障仍分别执行自己的鉴权、披露与
   生命周期合同；
3. 请求被分类为 `behavior_exploration` 后，系统必须在读取 review / restricted 证据前，针对当前 Bot / Event
   在模型外确认提问者是 `SUPERUSER`；失败时不检索、不拼装完整解释；
4. 鉴权通过后，完整行为解释可以在请求发起的原始私聊、群聊或频道原路返回。系统不再要求房间 allowlist、
   其他成员逐一鉴权、强制转私聊或二次风险确认；请求者负责选择合适的会话，并承担该平台参与者可见性与消息
   留存带来的后果；
5. 上一条只取消基于会话参与者构成的额外投递门。回答仍只能包含证据政策允许且已经净化的内容；Token、
   原始或未脱敏配置、私密日志、原始消息、绝对本机路径及其他秘密不得进入索引或回答。结构观察、行为观察、
   静态推导、未知、partial 与 stale 仍必须如实区分；
6. `SUPERUSER` 的聊天投递授权不自动授权把 restricted 源码、配置证据或运行证据发送给远端模型。Provider
   与数据类别仍需部署侧独立、显式授权；这不是要求用户在聊天中切换显式模式；
7. 允许私聊进入统一分流不等于自动开放私聊报障。当前 `suspected_incident` 的私聊受理仍由报障生命周期
   合同单独限制；若要在私聊创建或续接 incident，需要另行决定所有权、关联和披露边界；
8. 对当前请求原路发送受控解释不属于 ADR-0025 所禁止的主动诊断副作用。系统仍不得借行为探索向其他目标
   主动发消息、运行探针、修改配置、执行插件代码或执行外部写入。

## 选择理由

- 统一入口负责接收和分类自然语言，场景能力不应在分类前被一个历史报障切片整体截断；
- `SUPERUSER` 是部署者已经配置的模型外高权限边界，足以让请求者决定聊天消息发到哪个会话；
- 不检查旁观者可以避免无法可靠实现的成员认证，也避免把运维协作强制收敛到单一平台场景；
- 把会话可见性责任与内容安全、模型外发授权分开，既允许完整解释落地，也不会把高权限身份误写成无限披露。

## 没有选择的方案

### 完整解释只允许私聊或本机 CLI

没有选择。它会阻止团队在私有群聊、隔离服务器或运维频道协作，而且私聊也不天然保证平台留存更安全。

### 为可接收完整解释的群聊和频道维护 allowlist

没有选择。房间是否合适由发问的 `SUPERUSER` 负责；额外 allowlist 增加配置和漂移，却仍不能证明每个旁观者
都合格。

### 只开放行为探索的专用私聊命令

没有选择。私聊应进入与其他场景相同的自然语言意图分流；行为探索是 disposition，不是第二套入口语法。

### `SUPERUSER` 可以关闭所有净化与模型外发限制

没有选择。聊天接收者授权、秘密处理与外部 Provider 数据授权是不同安全域，不能由一个身份标记合并。

## 带来的影响

- 入口适配层需要把当前分类前的全局私聊拒绝下移到具体 disposition / 服务边界；
- 公开教学、用法纠错和澄清可以在私聊原路返回；行为探索必须先鉴权再读取 restricted 证据；
- 报障服务现有私聊拒绝继续保留，因此本决定不会静默改变 incident 的所有权或关联语义；
- 行为解释格式化器继续执行 mention / 控制字符净化与证据披露过滤，但不检查会话成员构成；
- 测试需要覆盖私聊、群聊和频道中的 `SUPERUSER` 原路回复、非 `SUPERUSER` 在检索前失败关闭，以及私聊
  疑似故障仍由报障服务拒绝。

## 落实与确认

- **当前实现**：私聊已可进入统一守门和意图分流；`LiveReportService` 继续独立拒绝私聊报障。
- **可复用基础**：Alconna / UniSeg 的 Target 与消息发送已能表达私聊、群聊和频道；会话 scope 也已包含
  private 维度。
- **尚未实现**：私聊行为探索的 `SUPERUSER` 鉴权、restricted 证据读取与原路回复；当前只覆盖私聊公开教学
  及私聊故障仍被服务拒绝的回归测试。
- 本 ADR 只确认入口与投递合同，不授权实施运行代码或开放私聊 incident。
