# ADR-0025：用多源部署证据向开发者解释插件行为

| 状态 | 决策日期 |
|---|---|
| 已采纳；第 7 条的配置值模型输入边界由 ADR-0029 部分替代 | 2026-08-12 |

## 当时遇到了什么

部署本地能力影子已经可以发现当前加载的 Plugin、Matcher 和 Alconna，并向通过鉴权的维护者返回带
披露标签的候选。但这条链主要回答“发现了什么能力”，还不能完整解释“某项行为为什么在当前部署中这样
表现”。

插件行为可能同时取决于运行时注册结构、源码分支、有效配置、NoneBot / 适配器 / 插件及关键依赖版本、
事件场景、身份权限、限流、外部服务状态和已有运行观察。源码摘要只能证明制品是否变化，不等于源码语义；
源码本身也不能证明当前配置已经满足、动态分支已经走过或外部服务当前可用。

## 决策

1. 增加“面向已鉴权开发者的插件行为探索”产品边界。开发者无需打开仓库，即可在安全可得证据范围内询问
   插件的能力、触发条件、配置影响、环境约束和当前部署表现；实现细节只是可询问内容和证据来源的一部分，
   不是能力的全部范围。证据不足的问题必须保留未知或拒绝推断，不承诺所有行为问题都能得到确定答案。
2. 该能力面向经过模型外鉴权的部署开发者，不改变普通用户的公开能力范围。首个 NoneBot 运行入口使用当前
   Bot / Event 的 `SUPERUSER` 检查；未来其他开发者入口也必须提供等价的模型外鉴权，不能因更换入口而扩大
   披露范围。鉴权只扩大可读取证据的范围，不提高证据置信度，不证明能力当前可执行，也不授权修改配置、
   运行探针或扩大日志采集。
3. 行为解释可以协调与问题相关的多源证据：
   - 当前运行时已经注册的 Plugin、Matcher、Alconna 和适配器结构；
   - 源码、配置模型、PluginMetadata、帮助数据和文档中的字段级证据；
   - 按白名单分类和脱敏的有效配置状态；
   - NoneBot、插件、适配器和关键依赖的版本或源码 revision；
   - 系统已经按既有授权安全采集的运行观察和回执。
   任何来源都只证明自己观察或声明的字段；源码不是整份权威真值。
4. 每项实质结论必须说明证据性质：
   - **已观察事实**：进一步区分启动或快照时观察到的结构，与某次请求中实际发生的行为。已加载、已注册或
     字段存在不能冒充 Matcher 已命中、分支已走过或配置已生效；
   - **静态推导**：由源码、配置模型、元数据或文档交叉推导，但尚未在当前行为路径中观察；
   - **仍然未知**：动态 Permission、Rule、handler 分支、外部状态、采集缺口或证据冲突使系统无法安全判断。
   `partial`、`stale`、冲突和 `opaque` 必须随结论暴露，不能包装成当前事实；没有运行观察也不能反向证明
   某项行为没有发生。
5. 面向开发者的行为解释至少应给出：行为结论、适用前提、证据支持的最短行为路径、当前部署证据、来源与
   revision，以及仍未知或需要另行验证的部分。只有证据足够时才展示具体调用流、配置影响或源码位置；
   获准展示的源码定位使用相对路径、符号或受控 source span，不直接回显绝对本机路径。
6. 新增的行为探索采集与解释路径保持只读：不额外 import 或加载插件，不调用第三方 Rule、Permission、
   handler、parser、template、behavior 或 executor，不主动运行探针，不修改配置，不发送消息，也不产生
   GitHub 或生产环境写入。现有显式公开 Provider 的可见性检查继续遵守原有合同，本决定不扩大可调用的
   第三方代码范围。任何扩大采集、真实执行或外部副作用都需要独立授权。
7. Token、密码、Cookie、私钥、`.env` 原文、原始配置值、私密日志和未脱敏运行数据不得进入索引、模型
   上下文或群聊回答。配置观察采用显式白名单与字段级敏感判断，只输出解释行为所需的安全派生状态；
   “某配置存在”本身可能敏感，不能默认披露。
8. 行为探索、指令教学和故障受理共享证据底座但保持不同职责：教学回答“怎样使用”，行为探索回答“为什么
   在当前部署中这样表现”，故障受理负责建立 incident、补证和维护者处理生命周期。本决定不建立三者之间
   的自动转诊、持续会话或统一持久 Case。
9. 本决定不规定该方向与用户功能反馈的排期或实施先后；两者的生命周期和实施安排分别决定。

## 为什么这样选

- 当前行为由代码和部署上下文共同决定，只读源码、README 或运行时注册对象中的任意单一来源都会遗漏
  重要条件；
- 明确区分结构观察、行为观察、静态推导和未知，可以避免把静态可能性冒充当前运行事实；
- 模型外鉴权、字段级披露和只读失败关闭延续现有能力影子的隐私与副作用边界；
- 独立的行为解释职责可以复用能力知识和运行观察，同时不把教学、探索和故障处理合并为同一业务生命周期。

## 没有采用的方案

### 只做源码实现探索

源码无法单独证明当前配置、版本、场景、权限、外部服务和实际运行路径，因此会把部署问题错误地解释成
实现问题。

### 只根据运行时注册对象解释行为

注册结构能证明能力被发现，但通常看不到 handler 内的配置分支、手写解析和动态条件，也不能解释某个
行为为什么发生。

### 把已加载、已配置或存在某段源码直接写成当前可执行

这些事实只覆盖部分前提。最终执行仍由原插件的 Permission、Rule、handler、限流、场景和外部状态决定。

### 为提高确定性而执行插件或读取原始配置与日志

这会把只读解释升级成探针或诊断执行，并扩大秘密、隐私和生产副作用边界，必须作为独立获授权动作处理。

## 带来的影响

- 现有能力影子可以作为一部分事实底座，但仍需补足源码语义、脱敏配置投影、环境 revision 协调、运行
  观察联接和行为解释输出合同；
- 证据不足时返回不完整、未知或拒答属于预期的失败关闭行为；
- 普通用户入口、公开能力披露和原插件的最终执行资格不因本决定改变；
- 本 ADR 不确定 AST / 代码图、RAG、LLM、embedding、缓存、持久化 schema、回答 UI 或远端源码外发方案；
- 本决定本身不引入需要跨重启恢复的权威业务状态或 ORM。

## 落实与确认

- **已有基础**：ADR-0021 的部署本地能力影子、ADR-0022 的模型外 `SUPERUSER` 鉴权、字段级
  Claim / Evidence / Constraint、源码位置与 revision，以及既有传输无关运行观察。
- **2026-08-12 实现检查点**：标准部署声明 / 制品 / 运行模块协调、有界源码函数证据、标准 Config 引用与
  策略先行投影、Evidence ID 闭包以及严格 Direct Request 客户端已有库级实现和假模型测试。
- **尚未实现**：开发者专属行为探索意图和路由、跨来源冲突协调、README / 帮助数据适配、后台分析与缓存、
  真实模型资格、持久语义知识和面向用户的完整行为解释卡。第三方自定义 Permission / Rule / 限流语义、
  运行观察与问题的安全联接也仍待实现。当前维护者回复仍只复述有限候选，不能描述为已经具备完整行为
  探索能力。
- 本 ADR 确认产品与安全边界，不授权实施计划，也不表示功能已经进入运行入口。
