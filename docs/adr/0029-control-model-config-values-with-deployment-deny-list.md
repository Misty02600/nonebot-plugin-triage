# ADR-0029：以部署者 deny-list 控制能力相关配置值进入模型

| 状态 | 决策日期 |
|---|---|
| 已采纳 | 2026-08-12 |

## 当时遇到了什么

插件的真实行为经常取决于部署配置。只分析配置 schema 和源码，可以知道某个开关或额度如何影响行为，
却不能确认当前部署选择了什么；完全禁止模型读取配置值，会让能力教学和行为解释长期停留在静态推导。

与此同时，NoneBot 社区通常把普通行为配置和 Token、Cookie、账号列表等受限值放在同一组 `.env`
配置中。让 LLM 判断哪个值可以读取，会把数据准入交给概率推断；为每个插件维护字段级 allow-list，又会给
部署者带来过高维护成本。因此需要一个简单、明确、由部署者掌握的值准入边界。

## 决策

1. 增加部署配置 `NBTRIAGE_RESTRICTED_CONFIG`。它使用 JSON 字符串数组列出不允许进入模型上下文的
   NoneBot 顶层配置键；列表是部署者的数据准入策略，LLM 不能添加、移除或覆盖其中的判断。
2. 配置键按 NoneBot 的大小写不敏感语义匹配。`FOO__BAR` 等嵌套键收敛为顶层 `foo`，因此限制顶层键
   会限制它的全部嵌套内容；`DISCORD_BOTS` 这类复合对象整项限制，不在第一版增加字段选择器。
3. 未来的配置值投影只能从与当前候选能力实际相关、且未被部署者限制的键中选择值，并且只能瞬时进入
   配置解释模型的当次上下文。系统不得上传整份 `.env`、完整 NoneBot `Config`，也不得枚举
   `os.environ` 后交给模型。
4. 第一版只支持 NoneBot 标准 `Config` / `get_plugin_config()` 配置链。系统不扫描插件中的
   `os.getenv()`、`os.environ` 等直接读取方式；无法从已验证配置实例取得的值保持未知，也不为分析重新
   执行插件 validator。
5. 无论部署者是否限制，配置原值都不得进入能力索引、持久缓存、日志、测试快照或 Bot 回答。允许进入
   模型的值只用于推导与行为有关的事实；这些事实能否对当前受众披露，仍由独立的模型前受众域和回答
   输出门决定。
6. 本决定采用 deny-list，而不是要求模型识别秘密或为所有插件建立人工 allow-list。部署者选择的模型
   可以看到未列入限制列表、且被能力相关性筛选出的值；部署者必须把不接受这一处理方式的顶层键加入
   `NBTRIAGE_RESTRICTED_CONFIG`。

## 为什么这样选

- 数据准入由明确配置决定，避免让 LLM 的语义分类兼任安全授权；
- 顶层键与现有 NoneBot 配置习惯一致，能用少量标注覆盖嵌套 Token、Bot 列表和插件复合配置；
- “只取能力相关键”限制发送范围，deny-list 则让部署者保留最终否决权；
- 模型输入和值对外披露使用不同守门边界，模型可以理解部署行为，但不能直接回显配置原值。

## 没有采用的方案

### 让 LLM 判断配置值是否敏感

模型可以帮助理解字段语义，但概率判断不能作为原值准入授权；误判一次就可能造成不可逆的数据外发。

### 只允许人工逐字段 allow-list

它能提供更保守的默认值，但会要求普通部署者理解每个第三方插件的配置模型，并持续维护大量字段标识，
不适合当前轻量部署目标。

### 在 `.env` 行内增加注释或复杂字段选择器

NoneBot 不提供通用的配置注释契约，嵌套 JSON、alias 和插件自定义解析也会使字段映射复杂化。第一版以顶层
键整项限制，牺牲细粒度换取可理解和可执行。

### 扫描所有直接环境变量读取

`os.getenv()`、动态环境变量名和自定义 helper 不属于统一的 NoneBot 配置链。第一版不为少数绕过标准
`Config` 的插件扩大静态分析范围；相关值不会因本决定自动进入模型。

## 带来的影响

- 部署者需要审视并列出不允许模型读取的顶层配置键；遗漏的相关值可能按所选模型的数据边界被处理；
- 一个顶层复合对象只要包含受限内容，就应整项加入 deny-list，这可能同时阻止模型利用其中的普通行为
  配置；
- 配置相关性筛选、模型上下文构造和回答披露仍需要独立实现与测试，不能仅凭
  `ConfigValuePolicy` 声称已经具备配置解释能力；
- 以后若需要支持直接环境变量读取或细粒度复合字段，必须重新评估映射可靠性与部署复杂度。

## 落实与确认

- **本次已实现**：`NBTriageConfig` 解析 JSON 数组 `NBTRIAGE_RESTRICTED_CONFIG`；
  `ConfigValuePolicy` 按大小写不敏感、`__` 收敛顶层的规则判定限制键，并由插件 runtime 持有。策略配置
  自身始终视为受限值。
- **2026-08-12 实现检查点**：已加载插件的标准 Config 引用、有界值投影、一次性能力分析请求及严格
  Direct Request 客户端已有库级实现和假模型闭环。restricted、缺失、Secret 或不透明值只形成 unknown，
  不得作为正向语义结论的配置证据。
- **仍未接入产品运行路径**：Bot handler、启动后台分析和真实模型资格均未启用，因此当前部署不会因本
  配置自动产生模型请求；模型输出也尚未进入持久知识或普通用户回答。
- 本 ADR 不授权读取整份配置、启动 Bot、执行第三方插件代码或增加外部模型调用。
